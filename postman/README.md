# Pharmassist — Postman

ملف المجموعة: `Pharmassist.postman_collection.json`، وملف البيئة: `Pharmassist.local.postman_environment.json`.

1. شغّل API محلياً بالأمر `php artisan serve`. تستخدم البيئة العنوان `http://127.0.0.1:8000` ويمكن تغيير `baseUrl` إذا اختلف المنفذ.
2. جهّز قاعدة MySQL الحالية وشغّل `php artisan migrate` ثم `php artisan db:seed`. البذور تنشئ الأدوية والشركات والدفعات والموردين ومديراً وصيدلياً تجريبيين في البيئة المحلية.
3. في Postman اختر **Import** واستورد ملف المجموعة وملف البيئة، ثم اختر بيئة **Pharmassist | محلي**.
4. بيانات الدخول جاهزة في البيئة: المدير `demo_admin` / `DemoAdmin2026!`، والصيدلي `demo_pharmacist` / `DemoPharmacist2026!`. الحسابان تجريبيان فقط، والبذور لا تنشئهما خارج `local` أو `testing`.
5. افتح المجلد **00 | تجربة جاهزة بنقرة Run** واضغط **Run folder**. يسجّل دخول المدير، يختار دواء ذا كمية قابلة للبيع، يبيع وحدة، يقرأ توزيع الدفعات، يعيدها، ويتحقق من عودة كمية المخزون، ثم يقرأ الإرجاعات وتقرير صافي المبيعات. احتفظ بقيم البيئة بعد التشغيل إذا أردت استخدام المعرّفات في بقية الطلبات.

المجلدات 01–06 تشمل بقية مسارات `routes/api.php` وتسجيل دخول الصيدلي. طلبات إنشاء الصيدلي والدواء تلتقط المعرّفات في البيئة. طلب التوريد لا يعيد `purchase_id` في استجابة الإنشاء حالياً؛ شغّل طلب **عرض طلبات التوريد وحفظ أحدث معرّف** بعده، ثم **تفاصيل دورة الطلب** لالتقاط معرّف البند. عند وجود أكثر من بند، عدّل مصفوفة `batches` في طلب الاستلام لتشمل كل بند وكميته.

رفع ملف التسعير يتطلب اختيار ملف Excel (`xlsx` أو `xls`) مطابقاً للطلب؛ Postman لا ينشئ ملف المورّد تلقائياً. تسلسل التوريد هو `Requested → Priced → Approved → Received`. طلبات الحذف، التلف، تعديل الجرد، الرفض والإلغاء تغيّر بيانات فعلية؛ شغّلها على بيانات تجريبية بعد مراجعة المعرّفات. لوحة الإدارة عبر المتصفح تستخدم جلسة ويب مستقلة، لذلك هذه المجموعة تغطي API فقط.

لإعادة توليد الملفات بعد تحديث المسارات: `python postman/build_collection.py`.
